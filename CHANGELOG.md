# Changelog

## [Unreleased]

### Added

- Initial release: `Scry.Engine.Neo4j` -- a real `Scry.Core.EngineBehaviour` implementation over Neo4j, via `boltx`. Replaces `scry_graph`'s own reference implementation (`Scry.Graph.Executor`, a naive recursive-DFS path enumerator over an in-memory graph) with genuine `SHORTEST`/variable-length-relationship-pattern execution against a real graph database -- the graph kind's first real adapter, closing the one kind with zero real-backend validation up to this point. Like `scry_search`/`scry_logic` (replaced by `scry_engine_redisearch`/`scry_engine_elasticsearch`/`scry_engine_episteme`), `graph` has no separate engine tier in its own reference form, so this package implements `Scry.Core.EngineBehaviour` directly too, translating `VIA` into a real Cypher traversal (`Scry.Engine.Neo4j.Cypher`) rather than calling `Scry.Graph.Executor` at all.
  **Driver choice**: `bolt_sips` (impl_spec.md's own roadmap driver) is confirmed stale (last Hex release April 2021, its own README now recommends `boltx`); `boltx` itself is pre-1.0 but the better of the two real options -- `DBConnection`-based, with clean typed `Node`/`Relationship`/`Path` structs.
  **Only the traversal shape is ever compiled to Cypher** -- every one of `VIA`'s own `WHERE`/`ORDER BY`/`DISTINCT`/`LIMIT`/`OFFSET`, and the top-level query's own `WHERE`/`GROUP BY`/aggregates/`ORDER BY`/`LIMIT`/`OFFSET`/projection, apply generically via `Scry.Core.QueryOps.run_flat/3`, the same posture the reference `Executor` itself already uses, sidestepping the "does Cypher's own `NULL` handling for a schemaless node match Scry's own semantics" question entirely.
  **Two real findings, not assumed**: Cypher's variable-length relationship pattern does not enforce simple-path semantics by default (a real, confirmed divergence from the reference's own true simple-path DFS, fixed with a standard, plugin-free `WHERE ALL(...)` idiom, confirmed to compose cleanly with `SHORTEST 1`); a `boltx` 0.0.6 connection-process crash on certain `FAILURE` responses is real, not hypothetical (`Scry.Engine.Neo4j.Conn.query/3` wraps every call in `rescue` and normalizes it to an ordinary `{:error, {:query_error, reason}}`).
  **One stated, deliberate divergence**: Neo4j's `SHORTEST 1` clause returns exactly one shortest path per reachable end node, where the reference's own `keep_shortest/1` keeps every path tied for minimum length -- documented, and asserted around directly, in `test/scry/engine/neo4j/parity_test.exs`.
  **Parity tested against the reference**: AGENTS.md's "Parity between multiple implementations" rule applied directly -- the same parsed `VIA`/`PATH` queries run against both a real Neo4j container and `scry_graph`'s own in-memory reference `Executor`, asserting matching projected results.
